# Accuracy Strategy

技術文書レビューで単一の「AI 正解率」だけを見ると、改善箇所が分からなくなります。

公開サンプルでは実案件の評価値や評価セットを使用しません。その代わり、評価を分けて考える方針だけを示します。

## 1. Extraction

元文書から必要な項目を正しく取り出せたか。

## 2. Normalization

同じ意味の値を共通形式へ正しく揃えられたか。

## 3. Comparison / Decision

比較対象と条件が正しく、不要な Finding や見逃しが発生していないか。

## 4. End-to-End Review

最終的に、レビュー担当者が必要な問題と根拠へ到達できたか。

## このリポジトリでテストすること

- 一致する値から Finding を作らない
- 不一致がある場合だけ Finding を作る
- Finding に複数文書の Evidence を残す
- 最終判断を `needs_review` として人へ渡す

実際の精度評価を行う場合は、評価単位、対象文書、ラベル付きデータ、サンプル数、閾値を先に固定する必要があります。
